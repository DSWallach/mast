## Root cause of the large group (class b, test isolation, not code or host)
`crates/engine/tests/it/main.rs` folds ~100 formerly separate test files into ONE binary. Under `cargo test`
all tests share one process, so single-test-binary files that mutate process env now leak into every other test:
- work_outline_kill_switch.rs:16 sets MAST_DISABLE_WORK_OUTLINE_WRITES=1 -> ~155 `work-outline/writesDisabled` panics.
- github_cli_login_shell.rs:94 sets PATH=<shim dir>, HOME, SHELL; pr_ticket_cache_login_shell.rs:92 sets PATH=".";
  codex_login_resolver.rs:31 sets PATH="/usr/bin:/bin"; -> ~100 `git spawns/runs: NotFound` (m5_*, merge_queue, diff_sync_*, external_import_*, etc.).
- other tests then hit the 4-running-commands cap (agent_tools "already has 4 commands running") and 10 s timeouts.
Those files carried "SAFETY: single-test binary" comments, which stopped being true after consolidation under cargo test; they now call `require_process_per_test`, which fails fast outside nextest.
Not host state: load 5.6, inotify 256 instances, runner env (HOME/PATH/git identity all fine) are irrelevant to the 324.
The earlier "~12 failures" W3-T2 run (/tmp/w3t2-final-full.log) was `cargo nextest` on slot a (7 failures, 3110 tests).
The 327-failure runs and /tmp/full-{base,head}-1.log (330 failed lines) used `cargo test`. Code did not change; the runner did.
