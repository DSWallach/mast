# First-run audit

Audit of `origin/work-outline-implementation` at `0892ac0d`, 2026-11-05. This is a headless audit; no GUI was opened. The clean build and isolated runtime checks are described below. Findings below distinguish source inspection from observed execution.

## Findings

1. **Medium — headless-first startup can select legacy settings.** Headed startup calls the migration before logging creates the directory (`apps/mast/src/main.rs:136`), but headless startup skips it and creates the directory for logs (`:158`). A subsequent first headed launch classifies any existing data directory as an existing profile (`crates/ui/src/settings.rs:1689`), selecting legacy values rather than the Neutral defaults 1B table. This is a source-derived scenario, not yet exercised. **Fix:** classify before headless or headed startup, using saved settings or registry Space/chat data rather than startup-only files.

2. **Medium — packaging has undeclared Python dependency and repeats the build.** README.md:44–58 says to build the installed profile and then run `scripts/package-macos.sh`; the script builds a separate release profile (`scripts/package-macos.sh:31`) and installs `dmgbuild` through pip (`:115`–`:117`). A fresh macOS may not have pip or may prevent user installation. **Fix:** document Python 3, pip, dmgbuild and the second build on this branch; longer term make packaging reuse a selected build.

3. **Medium — packaging ignores a custom Cargo target directory.** `scripts/package-macos.sh:25` and `:35` hard-code `target/`, whereas Cargo honours `CARGO_TARGET_DIR`. With that environment variable the release build and the binary copied into the bundle differ, or packaging fails. **Fix:** obtain the target directory from Cargo metadata and package the executable emitted by the current build; reject missing artifacts before touching package outputs.

4. **Low — PR error mentions a specific employer.** `crates/ui/src/pr_review_launch.rs:128` tells every user to add Cofactr's workspace superproject. **Fix:** generic repository-folder instruction on this branch.

5. **Low — getting-started describes GitHub authentication as mandatory.** `docs/guide/getting-started.md:7` lists `gh` with prerequisites for a first chat, whereas README.md:41 restricts it to PR features. **Fix:** identify it as optional and require sign-in for GitHub features on this branch.

6. **Medium — launch RPC can say “started” after the session errors.** With Codex absent from the isolated PATH, `CreateChatForWorkItem` returned `queued`; `WatchSessions` then reported `errored`, while repeating the same launch operation returned `started`. `crates/engine/src/work_outline_launch.rs:964` maps an applied command to started, whereas the harness can fail asynchronously (`crates/engine/src/sessions.rs:2640`). The Start Chat UI and an installed-but-signed-out CLI were not exercised, so this is an RPC contract finding, not a claim about the visible error. **Fix:** reject an unavailable harness before creating the chat, with an actionable error forwarded to the Start Chat dialog. This addresses the absent-CLI case; other asynchronous failures can still occur after delivery.

Packaging was inspected, not executed: it deletes outputs and the dev script opens a GUI.
