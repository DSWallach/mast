# W5-T5: scheduled pins flow and cache performance

- The `scheduled-pins` UI flow now starts with nothing pinned, pins from the row menu, collapses, restarts the app, opens the pinned task's run and unpins it. The UI driver gains `right_click` and `restart` steps, the chat menu's Pin row gets a driver selector, and the `scheduled-pins` world preset starts with both tasks unpinned.
- The SWR cache (Linear and PR lists) no longer serializes the whole cache, copies an entry or frees a replaced one while holding its lock. A refresh used to block readers for up to about 20 ms at 32 cached keys; the pure lock wait is now about a microsecond at every size.
- Overview List mode is unchanged: measured at 250 and 1,000 chats, nothing beat the baseline by more than 2× MAD.
- Test-only additions: the `swr_bench` test target (one `[[test]]` entry in `crates/engine/Cargo.toml`) and a parameterized `overview_bench`.
