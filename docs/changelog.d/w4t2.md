# W4-T2: quota broker

- New `mast_engine::quota_broker`. It is not wired into orchestration yet, so Mast's behaviour does not change.
- It defines the probe and local-usage fallback interfaces and a `poll_due` step with 90 s (180 s for `agy /usage`) intervals that does nothing while orchestration is inactive. There is no production probe, fallback or poll loop yet. A provider that needs sign-in or has unknown usage is never dispatched to.
- `BalancedFailover` (default): dispatch is weighted by headroom below the 85% hard cap, stays on the current provider until it reaches 78% and another provider below 78% has room, and answers `PauseAll` with the earliest time to try again when no provider is eligible.
- `PinnedFreeze`: never fails over; answers `Freeze` when work would pass 90%.
- Dispatch reserves its cost atomically. A successful poll drops reservations at least one poll interval old, and any reservation expires after 10 minutes.
- Upcoming: polling Antigravity, Claude Code and Codex usage while orchestration is active (read-only, never refreshing single-use OAuth tokens), with local token usage as the fallback when a probe fails.
- Upcoming (needs W3-T2 to land): act on `PauseAll` and `Freeze` (pause, freeze, checkpoint, notify), wire `QuotaBroker::status_payload()` (under 550 B) into the `quota_status` tool, and add `wake_header()` as a one-line header from the soft cap. Requires admission to `tool_catalog.rs`, `agent_tools.rs` and `crates/proto/**`.
