- Orchestrating: workers started with `create_chat` take a path lease on their item's `ownedPaths`. Up to 4 workers per project run at once when their paths are disjoint. A launch whose paths overlap a running worker, that would be a second writer of a hot path (`Cargo.lock`, the workspace `Cargo.toml`, `crates/proto/**`, `tool_catalog.rs`, a crate-root `lib.rs`, `apps/mast/src/main.rs`), or that would be a fifth worker is refused with `Path lease: queued behind <work item>: …` and can be retried once the holder finishes.
- Orchestrating: with worker worktrees on, only a `WorkspaceWrite` implementation worker gets a pre-created `.worktrees/<label>/<slug>` checkout, and its branch is now `work/<slug>` (never `mast/*`). Read-only chats, Managers, Leads, reviewers and spec auditors start in the shared checkout with no worktree setup before their first turn.
- Orchestrating: a `trivial` task that owns one or two files and touches no hot path is a `DirectSingleAgent` launch: one worker, no Lead.
