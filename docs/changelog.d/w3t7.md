# Worker continuation by hand-off

- `create_chat` / `chat_launch_child_for_item` for an item whose worker (a chat you created) stopped on an error, such as a usage limit, now continues that worker as a hand-off: the successor keeps the assignment, lineage, worktree, model, context window and Auto choice, the old worker is archived only after the successor starts, and its workers and pending wakes move over once. A worker that is running is never duplicated, and an idle worker is still reused as before. Name a harness or model, or pass `newChat` (`separate`), to start a separate reviewer or parallel assignment instead. If the hand-off does not start, the old worker keeps the assignment and the error says so.
- `hand_off_orchestrator` accepts `contextWindow` and `modelOptions`, so a successor made by an agent gets the window it asked for. Without them it inherits the source chat's options.
- `hand_off_orchestrator` accepts `sourceChat`: a coordinator or Manager hands off a stalled chat it created, or one on an item in its subtree or project (a worker at its usage limit that cannot run a turn). The successor takes that chat's item, configuration and permissions, never the caller's; the stalled chat is archived once the successor starts. Not for Manager or assistant chats.
- The credit-limit successor is a real hand-off: it records lineage, moves the stalled chat's own workers and wakes, and still keeps the stalled chat. A chat that already handed off, or that holds a standing role, gets a plain successor as before.
- A chat's parent follows recorded hand-offs through archived chats (`live_parent`). Hand-off and its replay move every live chat under the source, including ones made or restored later, to the successor; successors copy the live parent; chats left under an archived predecessor are repaired when the engine opens.
- Cherry-picked from `david-rolling`: 394255ceb (the hand-off dialog's model options reach the successor) and 939a03af6 (its test), now on this branch as 7599eeaa9 and 50ddcebd9.
- Known limitation: a worker that stopped is continued only while the engine still knows its last turn errored. After an engine restart the worker has no session, so a launch for its item starts a second chat instead of continuing it; the fix is planned for the next stage.
- Not in this change: the hand-off dialog's success notice and an "Open successor" entry for an archived source (E3), and the peer-created coordinator parent link (F).
